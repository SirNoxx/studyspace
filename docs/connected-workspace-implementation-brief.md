# Studyspace: unified workspace implementation brief

Act as the senior product engineer responsible for shipping these changes across the web and Windows desktop app. Implement working product flows, persistent data, migrations, authorization, automated tests, and release documentation. Audit the existing editor, local storage, authentication, community APIs and desktop isolation before making changes. Preserve existing notes, attachments, module content, account identities and collaboration history.

## Product requirements

1. **One workspace.** Personal notes live on the device and remain editable offline. Signing in enables cloud identity, AI, Discover, messaging, shared collections and shared planning in the same interface. Remove the requirement to switch local/cloud workspaces. Explicitly shared content is stored in the cloud; personal notes are never uploaded simply because a user signs in. Migrate existing local and cloud notes without overwriting, duplicating or silently deleting work. Retain an explicit recovery/export path.
2. **Whiteboard text.** Clicking with the Text tool places an editable text box directly on the board. Provide a corner resize handle, wrapped multiline text, and selected-box controls for font size, bold, italic and color. Support moving, deletion, undo/redo and persistence alongside drawing tools. Include text and its formatting in exported boards and study context. Resizing must retain the full text; support keyboard resizing and keep typing focus during autosave.
3. **Pinning.** Pinning changes sibling ordering only. A pinned note remains inside its current folder or collection and appears before unpinned siblings. Preserve existing pinned notes and provide a safe migration for legacy detached pins.
4. **Shared notes.** Use the regular note editor and rendered modules in shared collections, including code, whiteboards, tables and diagrams. Preserve role enforcement, revision checks, conflict comparison, recoverable drafts, history and restoration. Editors can edit; Viewers cannot mutate content.
5. **Identity and invitations.** Add Google Sign-In through Supabase and support secure desktop OAuth. Invite collaborators by email with privacy-preserving responses, owner-only authorization, duplicate prevention, revocation and acceptance by the intended verified account. Invitations to people without accounts must remain claimable after signup. Email delivery must be observable and retryable.
6. **Links.** The paste/import link flow offers editable title and author fields, prefilled from metadata when available. Metadata failures must not prevent saving the original link.
7. **Planning and calendar.** Add adjacent Planner and Calendar controls at the top of the collections sidebar. Provide task creation, editing, completion, priorities, due dates/times, descriptions, filtering and overdue/upcoming views. Highlight today in all calendars and handle local time zones. Let users request planner collaboration; only accepted collaborators can receive shared tasks. Send task assignment/update emails according to notification preferences without exposing private tasks.
8. **Google Calendar.** Provide a separate opt-in connection with minimum OAuth scopes, secure refresh-token storage, calendar selection, event import, and explicit task-to-event synchronization. Handle time zones, all-day events, revoked tokens, retries, duplicate events and disconnect. Never silently import calendar data into public content.
9. **Document exchange.** Print notes with a clean content-only layout. Export Markdown, Word and PDF with titles, links, lists and tables. Import Markdown, text, Word and text-based PDF into editable Markdown with previews and useful conversion warnings. Identify scanned PDFs requiring OCR; never return a blank note as a successful import. Validate type and size, sanitize converted content and retain access to the original file where practical.
10. **Editing menus.** Replace separate right-click code/whiteboard insertion entries with one Add a module entry. Keep other relevant editing actions. Offer spelling suggestions when right-clicking a misspelled word without requiring a selection, preserving native clipboard and keyboard behavior.
11. **Desktop AI.** Diagnose the current desktop failure and make signed-in AI work with local notes using explicit selected-context sharing. Keep service keys on the server, enforce account quotas, preserve chat messages on failure, stream responses, support cancellation and show actionable authentication/offline errors.

## Engineering requirements and acceptance

- Separate device persistence from signed-in identity. Define typed boundaries for personal notes, shared documents, planner collaboration, calendar connections and invitation delivery.
- Enforce membership and ownership on the server/database, including attachment access, invitation acceptance and concurrent writes. Validate external input and protect OAuth callbacks against replay and cross-account linking.
- Preserve the existing visual language. Provide keyboard navigation, labels, focus management, responsive layouts, and loading, empty, offline and retry states.
- Test migrations from existing data, offline note edits, sign-in/out without data loss, account switching, owner/editor/viewer isolation, concurrent shared edits, invitation retries and revocation, calendar sync deduplication, document conversion, whiteboard persistence, and packaged desktop AI.
- Ship incrementally: editor improvements; unified persistence and desktop connectivity; identity/invitations and shared editor; planner/calendar integrations; document exchange; end-to-end release verification. Keep each stage reviewable and document rollback without deleting user data.
- Configure and verify available integrations. Clearly identify any external Google OAuth, consent-screen or email-provider configuration that requires the operator's account access. Do not describe unconfigured integrations as live or fake successful delivery.

Begin execution after writing this brief. Continue through implementation and verification; report completed behavior and any external setup dependencies accurately.
